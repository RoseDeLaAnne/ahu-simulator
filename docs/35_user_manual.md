# Руководство пользователя

Дата актуализации: 2026-05-11.

## О чем это руководство

Это руководство написано для человека, который открывает приложение и хочет
понять: что оно показывает, какие кнопки нажимать, где смотреть результат и
что делать, если что-то пошло не так.

Приложение моделирует работу приточной вентиляционной установки. В нем можно
выбрать готовый режим работы или вручную задать параметры: наружную
температуру, расход воздуха, мощность нагревателя, загрязнение фильтра,
скорость вентилятора и условия в помещении. После этого приложение рассчитывает
состояние установки и показывает результат на dashboard.

Важно: это учебный симулятор, а не промышленная система управления. Он не
подключается к реальным датчикам и не управляет оборудованием. Все значения
задаются пользователем или берутся из заранее подготовленных сценариев.

## Что умеет приложение

В обычной работе пользователь может:

- запустить симулятор на своем компьютере;
- открыть dashboard в браузере;
- выбрать один из готовых сценариев работы ПВУ;
- изменить параметры вручную и сразу увидеть новый расчет;
- посмотреть состояние установки на мнемосхеме;
- оценить температуру, расход, мощность, давление на фильтре и другие
  показатели;
- увидеть, находится режим в норме или уже попал в зону риска;
- сравнить два режима "до" и "после";
- сохранить удачный прогон в локальный архив;
- создать свой пользовательский сценарий;
- выгрузить отчет в CSV/PDF;
- перед защитой проверить, что демонстрация готова.

## Как запустить приложение

Самый простой вариант - открыть папку проекта и дважды нажать `start.bat`.

Скрипт сам подготовит окружение, установит зависимости, запустит сервер и
попробует открыть dashboard в браузере. Обычно адрес выглядит так:

```text
http://127.0.0.1:8000/dashboard
```

Если порт `8000` уже занят, приложение выберет другой свободный порт. В этом
случае ориентируйтесь на адрес, который написан в окне консоли.

Если браузер не открылся сам, это не ошибка. Скопируйте адрес из консоли и
откройте его вручную.

## Как проверить, что все запустилось

После запуска полезно открыть три страницы:

```text
http://127.0.0.1:<порт>/health
http://127.0.0.1:<порт>/dashboard
http://127.0.0.1:<порт>/docs
```

`/health` показывает, что backend работает. `/dashboard` - основной экран
пользователя. `/docs` - техническая страница с API, она нужна не каждый день,
но полезна при демонстрации проекта.

Если `/health` отвечает, значит сервер поднялся. Если при этом dashboard не
открыт, просто перейдите на `/dashboard` вручную.

## Основной экран

Dashboard - это главный экран приложения. На нем собраны:

- выбор сценария;
- поля для ручной настройки параметров;
- расчетные показатели;
- мнемосхема установки;
- графики изменения показателей во времени;
- список предупреждений;
- блоки для экспорта, сравнения и сохранения результатов;
- материалы для проверки и защиты проекта.

На экране используются три понятных статуса:

| Статус | Что означает |
| --- | --- |
| `Норма` | Режим выглядит рабочим, показатели в допустимой зоне. |
| `Риск` | Один или несколько показателей подошли к опасной зоне. |
| `Авария` | Есть критическое отклонение, режим требует внимания. |

Если видите `Риск` или `Авария`, это не означает, что программа сломалась.
Наоборот, симулятор показывает, что выбранные параметры привели установку в
нежелательный режим.

## С чего начать работу

Для первого запуска лучше выбрать сценарий `Межсезонье`. Это спокойный режим,
на котором удобно понять экран: показатели не экстремальные, мнемосхема
читается, тревоги не отвлекают от знакомства с приложением.

Дальше можно попробовать такой порядок:

1. Запустите приложение через `start.bat`.
2. Откройте `/dashboard`.
3. Выберите сценарий `Межсезонье`.
4. Посмотрите на общий статус и основные показатели.
5. Увеличьте загрязнение фильтра.
6. Проверьте, как изменились давление на фильтре, расход и статус.
7. Переключитесь на сценарий `Зима` или `Загрязнение фильтра`.
8. Сравните поведение установки в разных условиях.

Такой путь помогает быстро увидеть главную идею продукта: параметры меняются,
а расчет, статусы, графики и визуализация реагируют на эти изменения.

## Готовые сценарии

В приложении есть несколько заранее подготовленных режимов.

| Сценарий | Для чего нужен |
| --- | --- |
| `Зима` | Показ работы нагревателя и рекуперации при холодном наружном воздухе. |
| `Лето` | Режим с теплым наружным воздухом и небольшой потребностью в нагреве. |
| `Пик нагрузки` | Проверка установки при повышенном расходе и тепловой нагрузке. |
| `Межсезонье` | Базовый режим для спокойной демонстрации. |
| `Снижение подачи` | Показ влияния уменьшенного расхода воздуха. |
| `Загрязнение фильтра` | Демонстрация роста сопротивления фильтра и появления предупреждений. |
| `Ручной режим` | Показ ситуации, когда автоматика заменена ручным управлением. |

Системные сценарии лучше воспринимать как учебные примеры. Их можно применять,
сравнивать между собой и использовать как отправную точку для ручных настроек.

## Какие параметры можно менять

Пользователь работает с параметрами, которые понятны с инженерной точки зрения:

| Параметр | Простое объяснение |
| --- | --- |
| Наружная температура | Каким воздух поступает с улицы. |
| Расход воздуха | Сколько воздуха установка должна подать в помещение. |
| Уставка температуры притока | Какую температуру приточного воздуха хотим получить. |
| Эффективность рекуперации | Насколько хорошо установка возвращает тепло. |
| Мощность нагревателя | Сколько тепла может добавить нагреватель. |
| Загрязнение фильтра | Насколько фильтр мешает прохождению воздуха. |
| Скорость вентилятора | Как активно работает вентилятор. |
| Температура помещения | Начальное состояние помещения. |
| Тепловая нагрузка помещения | Внутренние теплопритоки или потери. |
| Режим управления | Автоматический или ручной режим. |

Если задать физически невозможное значение, приложение не должно принимать его
как корректный вход. Например, расход или температура имеют допустимые
диапазоны.

## Как читать результаты

После расчета обращайте внимание не на одну цифру, а на картину целиком.

Сначала посмотрите общий статус: `Норма`, `Риск` или `Авария`. Затем проверьте
ключевые показатели:

- температуру приточного воздуха;
- температуру помещения;
- фактический расход;
- мощность нагрева;
- суммарную мощность;
- перепад давления на фильтре;
- сообщения в блоке предупреждений;
- графики изменения показателей во времени.

Например, если сильно загрязнить фильтр, логично ожидать рост перепада
давления и возможное снижение расхода. Если наружная температура очень низкая,
важно смотреть, хватает ли нагревателю мощности для поддержания уставки.

## Мнемосхема установки

Мнемосхема показывает установку как технологическую цепочку:

```text
наружный воздух -> фильтр -> рекуперация -> нагреватель -> вентилятор -> помещение
```

Она помогает объяснить расчет визуально. При изменении параметров меняются
статусы узлов, подписи и предупреждения. Для демонстрации это часто удобнее,
чем сразу показывать таблицы.

Если 3D-режим или WebGL на конкретном компьютере работает нестабильно,
используйте 2D-мнемосхему. Это нормальный и предусмотренный вариант показа.

## Simulation Session

`Simulation Session` нужна, когда расчет хочется показать как процесс во
времени, а не как один статичный результат.

Обычно используются такие действия:

- `Старт` - начать проигрывание;
- `Пауза` - остановить;
- `Шаг` - выполнить один шаг вручную;
- изменение скорости - ускорить или замедлить проигрывание;
- `Сброс` - вернуться к исходному состоянию.

Во время запущенной сессии часть ручных настроек может быть недоступна. Это
сделано специально, чтобы пользователь не менял параметры посреди
автоматического проигрывания и не получал смешанный результат.

## Отчеты

Для подготовки материалов используйте `Export Pack`.

Обычный порядок такой:

1. Выберите сценарий или настройте параметры вручную.
2. Убедитесь, что расчет на dashboard выглядит правильно.
3. Откройте блок `Export Pack`.
4. Сформируйте отчет.
5. Откройте или скачайте получившиеся файлы.

В результате создаются:

- CSV-файл с расчетными данными;
- PDF-отчет для просмотра и передачи;
- manifest-файл со служебным описанием набора.

В обычном запуске файлы появляются в `artifacts/exports/<дата>/`. В desktop
сборке они могут сохраняться в `%LOCALAPPDATA%\AhuSimulator`.

## Сравнение "до" и "после"

Блок `Run Comparison` помогает показать, что изменилось после настройки
параметров.

Пример:

1. Выберите спокойный режим и зафиксируйте его как `До`.
2. Увеличьте загрязнение фильтра или измените расход.
3. Зафиксируйте новый режим как `После`.
4. Постройте сравнение.
5. Посмотрите, какие показатели улучшились, ухудшились или остались почти без
   изменений.

Сравнивать можно только совместимые прогоны. Если приложение сообщает, что
пара несовместима, выберите два прогона с одинаковым горизонтом и шагом
расчета.

## Архив сценариев

`Scenario Archive` сохраняет локальные снимки прогонов. Это удобно, если вы
подобрали хороший режим для демонстрации и не хотите набирать его заново.

Архив можно использовать как рабочую историю: сохранить несколько показательных
режимов, вернуться к ним позже и использовать их для сравнения.

## Пользовательские пресеты

Помимо системных сценариев можно создать свой пресет. Он сохраняет текущие
параметры как отдельный пользовательский режим.

С пользовательскими пресетами можно:

- создать новый пресет;
- переименовать;
- обновить;
- удалить;
- экспортировать в JSON;
- импортировать из JSON.

Системные сценарии при этом не меняются. Это удобно: можно экспериментировать,
не опасаясь испортить базовые примеры.

## Журнал событий

`Event Log` фиксирует важные действия: запуск сценария, смену режима
управления, сборку отчета, сохранение в архив, значимые переходы статуса.

Журнал полезен, когда нужно восстановить ход демонстрации или показать, что
работа с моделью была последовательной и воспроизводимой.

## Проверка и обоснование модели

В dashboard есть блоки, которые помогают отвечать на вопрос "почему этому
расчету можно доверять в рамках учебной модели".

`Validation Matrix` показывает проверочные случаи. `Validation Basis` описывает
методическую основу. `Validation Agreement` связывает расчет с эталонными
точками. `Manual Check` нужен для ручной инженерной сверки.

Эти разделы особенно полезны на защите: они показывают, что проект состоит не
только из красивого экрана, но и из проверяемой расчетной логики.

## Подготовка к защите

Перед показом лучше пройти короткий чеклист:

1. Запустите приложение.
2. Проверьте `/health`.
3. Откройте `/dashboard`.
4. Выберите `Межсезонье` как спокойный стартовый режим.
5. Проверьте, что открываются сценарии и меняются показатели.
6. Сделайте один быстрый export.
7. Зафиксируйте простое сравнение "до/после".
8. Откройте `Demo Readiness`.
9. Держите рядом `Defense Pack`, если потребуется быстро пройти по сценарию
   демонстрации.

Если есть время, перед защитой также запустите:

```powershell
python -m pytest
```

## Если что-то пошло не так

| Ситуация | Что сделать |
| --- | --- |
| Dashboard не открылся сам | Откройте адрес из консоли вручную. |
| Порт `8000` занят | Используйте порт, который выбрал скрипт запуска. |
| `/health` не отвечает | Остановите старый процесс и запустите `start.bat` заново. |
| PowerShell блокирует скрипты | Запускайте через `start.bat` или `.cmd`-файлы. |
| Python не найден | Установите Python `3.12+` и добавьте его в `PATH`. |
| Отчет не появился | Сначала выполните build в `Export Pack`, потом проверьте `artifacts/exports`. |
| 3D не работает | Продолжайте показ через 2D, KPI, графики, отчеты и validation-блоки. |
| Android-приложение не открывает dashboard | Проверьте, что указан реальный HTTPS backend, а не `127.0.0.1`. |

## Короткий сценарий показа

Если нужно быстро показать продукт за 8-10 минут:

1. Откройте `/health`.
2. Перейдите на `/dashboard`.
3. Начните со сценария `Межсезонье`.
4. Покажите мнемосхему, KPI и графики.
5. Переключитесь на `Зима` или `Загрязнение фильтра`.
6. Объясните, почему статус изменился.
7. Запустите короткую Simulation Session.
8. Сформируйте отчет.
9. Сделайте сравнение "до/после".
10. Завершите показ блоками `Validation` и `Demo Readiness`.

## Ограничения, о которых стоит помнить

Симулятор показывает учебно-обобщенную модель ПВУ. Он помогает объяснить
логику работы установки, влияние параметров и расчетные зависимости, но не
заменяет паспортные данные конкретного оборудования и промышленный расчет.

В текущей версии нет подключения к реальным датчикам, многопользовательской
работы, авторизации и промышленного диспетчерского контура. Это осознанное
ограничение: проект сосредоточен на расчетной модели, демонстрации и
воспроизводимости результатов.
