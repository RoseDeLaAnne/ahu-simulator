# Руководство по эксплуатации программного комплекса

Имитационная модель приточной вентиляционной установки (ПВУ) — интерактивный
цифровой двойник для ООО «НПО "Каскад-ГРУП"». Документ описывает назначение,
установку, запуск, функционал, настройку и эксплуатацию комплекса.

---

## 1. Назначение и описание

Программный комплекс `ahu-simulator` — это интерактивная имитационная модель
приточной вентиляционной установки. В отличие от статичного ручного расчёта,
оператор меняет входные параметры (наружная температура, расход, уставка
притока, КПД рекуперации, мощность калорифера, загрязнение фильтра, скорость
вентилятора, нагрузка помещения) и сразу видит пересчёт: мнемосхему со статусами
(норма / риск / авария), 3D-сцену, тренды и тревоги.

Назначение для предприятия:

- наглядная инженерная модель установки для обучения персонала и студентов;
- проверка поведения установки в разных режимах без реального оборудования;
- задел под цифровой двойник и интеграцию со SCADA / OPC.

Ключевые возможности: связка 2D-мнемосхемы и 3D-сцены на одном наборе сигналов,
готовые сценарии (зима, межсезонье, снижение подачи, загрязнение фильтра, ручной
режим), сравнение прогонов, архив сценариев, экспорт CSV / PDF / ZIP, офлайн-запуск
на демонстрационном ПК, контейнеризация и сборка Windows-артефактов, автотесты.

---

## 2. Архитектура и стек

Комплекс построен на слоистой архитектуре:

- `simulation` — расчётное ядро (уравнения теплового баланса, параметры,
  состояние, политика статусов, тревоги, сценарии);
- `services` — оркестрация расчётов, экспорт, сравнение, журнал событий,
  валидация, готовность к демонстрации;
- `api` — REST-маршруты FastAPI;
- `ui` — дашборд на Dash, 2D-мнемосхема (SVG) и 3D-сцена (Three.js);
- `infrastructure` — настройки, пути времени выполнения, логирование.

Стек: Python, FastAPI, Dash, Pydantic, Plotly, Three.js, Blender (генерация
3D-моделей), Docker, PyInstaller.

## 3. Установка и запуск

### 3.1. Требования

- Python 3.12+ (целевая версия проекта — 3.14);
- современный браузер с поддержкой WebGL (для 3D-сцены).

### 3.2. Установка зависимостей

```
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

### 3.3. Запуск

Локальный запуск через скрипт:

```
.\deploy\run-local.ps1
```

Или напрямую:

```
python -m uvicorn app.main:app --app-dir src --reload
```

После запуска дашборд доступен по адресу `http://127.0.0.1:8000/dashboard/`.
Корневой адрес `/` перенаправляет на дашборд. Документация API (Swagger) —
по адресу `/docs`, встроенный справочник проекта — по адресу `/handbook`.

### 3.4. Поставка

Предусмотрены контейнеризация (Docker) и сборка автономного Windows-артефакта
(PyInstaller) для офлайн-запуска на демонстрационном ПК без установки Python.

## 4. Функционал

### 4.1. Дашборд

Основной экран `/dashboard/?theme=concept03&page=dashboard` состоит из шапки со
статусом и часами, левой панели сценариев и режимов, центрального холста, правой
панели статуса и KPI, нижней полосы артефактов и нижней навигации.

Центральный холст имеет вкладки:

- 3D Модель — трёхмерная сцена установки с выносками живых данных по узлам;
- Схема — 2D-мнемосхема ПВУ со статусами узлов;
- Параметры — входы оператора и выходы расчёта;
- Тренды — динамика температуры притока, температуры помещения, мощности и ΔP;
- Аларма — активные тревоги установки;
- Документация — ссылки на встроенный справочник.

Кнопка «Развернуть» в подстроке холста разворачивает центральную область на весь
экран (фокус-режим), скрывая боковые панели.

### 4.2. Дополнительные страницы

Нижняя навигация переключает страницы:

- Оборудование — состав установки. Карточки узлов кликабельны: выбор узла
  открывает карточку детали с расширенными характеристиками и живым сигналом
  узла (если он есть в модели).
- Управление — выбор режима работы (Автоматический, Полуавтоматический, Ручной,
  Тестовый/наладка). Выбор сразу применяется к работающей модели.
- Аналитика — экспорт отчётов по активному прогону (PDF, CSV, ZIP) и переходы к
  трендам и сравнению на дашборде.
- Библиотека — документация (открывается во встроенном просмотрщике) и пресеты
  сценариев (применяются к модели одним нажатием).
- Настройки — переключение темы и режима защиты, ссылки на справочник и Swagger,
  живая диагностика среды (WebGL, экран, браузер).

## 5. Эксплуатация

### 5.1. Сценарии и режимы

Готовые сценарии выбираются на левой панели дашборда или на странице
«Библиотека». Сценарии «Снижение подачи» и «Загрязнённый фильтр» намеренно
выводят установку в предупреждение и аварию — на них удобно демонстрировать
работу тревог.

Режим работы выбирается на левой панели или на странице «Управление». Числовые
уставки задаются на вкладке «Параметры» центрального холста.

### 5.2. Тревоги

Тревоги формируются расчётным ядром по порогам (перепад давления на фильтре,
отношение расхода, отклонение температуры притока, загрузка нагревателя, ручной
режим). Счётчик активных тревог отображается в строке тревог под шапкой, а
подробный список — на вкладке «Аларма». Уровни: предупреждение и авария; статус
установки и цвет индикатора шапки меняются соответственно.

Чтобы увидеть тревоги, выберите сценарий «Загрязнённый фильтр» (авария по
фильтру) или «Снижение подачи» (предупреждения).

### 5.3. Экспорт

На странице «Аналитика» доступен экспорт по активному прогону:

- PDF — сценарный отчёт с таблицами и выводами;
- CSV — временные ряды параметров;
- ZIP — архив с PDF, CSV и манифестом прогона.

Файл формируется на сервере и сразу скачивается браузером. Артефакты также
сохраняются в каталоге `artifacts/exports`.

### 5.4. Документация

Вкладка «Документация» центрального холста и страница «Библиотека» открывают
встроенный справочник `/handbook`, который отображает документы проекта в виде
оформленных HTML-страниц.

## 6. Настройка

### 6.1. Тема и режим защиты

На странице «Настройки» переключаются:

- тема оформления — `Concept03` (тёмная SCADA-тема) или `Legacy` (янтарная);
- режим — `Оператор` или `Защита` (defense-вариант для презентации).

Тема и режим задаются параметрами URL и применяются после перезагрузки
страницы: `?theme=concept03` / `?theme=legacy`, `?defense=1`.

### 6.2. Конфигурация по умолчанию

Значения по умолчанию хранятся в `config/defaults.yaml`: сценарий по умолчанию,
горизонт и шаг тренда, номинальный расход, пороги статусов, параметры CORS и
тему интерфейса. Сценарные пресеты — в `data/scenarios/presets.json`.

---

## 7. Диагностика и устранение неполадок

- 3D-сцена не отображается — проверьте поддержку WebGL в браузере (раздел
  «Диагностика» на странице «Настройки»). При отсутствии WebGL автоматически
  показывается 2D-мнемосхема.
- Изменения в Python-коде не применяются — перезапустите сервер (режим
  `--reload` бывает нестабилен); статические файлы (CSS / JS) подхватываются
  сразу.
- Документация не открывается — убедитесь, что сервер запущен; справочник
  доступен по адресу `/handbook`.

---

## 8. Тестирование

Автотесты запускаются командой `pytest`. Используются модульные тесты ядра и
интерфейса, интеграционные тесты API и сценарные тесты пресетов.
