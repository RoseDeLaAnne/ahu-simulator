## 🔧 Реализованные функции

### 1. Создание второй сцены
```javascript
_createComparisonSceneAfter()
```
- Создаёт `comparisonSceneAfter` с той же структурой, что и main scene
- Добавляет освещение (ambient, key, rim, fill lights)
- Создаёт environment и overlay roots
- Клонирует камеру для независимого управления

### 2. Загрузка модели для второй сцены
```javascript
_loadComparisonModelAfter()
```
- Клонирует модель из кэша (избегает повторной загрузки GLB)
- Строит node map для второй сцены
- Копирует binding map
- Добавляет модель в comparison scene

### 3. Применение signals к любой сцене
```javascript
_applyComparisonSignals(signals, side)
```
- Универсальная функция для применения signals
- Работает с "before" (main scene) или "after" (comparison scene)
- Использует соответствующий node map и binding map
- Применяет цвета статусов, температуру, мощность

### 4. Очистка второй сцены
```javascript
_disposeComparisonSceneAfter()
```
- Удаляет все объекты из comparison scene
- Освобождает память
- Сбрасывает все state переменные

## 🏗️ Архитектурные решения

### Клонирование модели
**Проблема:** Загрузка GLB файла дважды занимает время и память.  
**Решение:** `entry.root.clone(true)` создаёт копию из кэша.  
**Результат:** Мгновенная загрузка, экономия памяти.

### Отдельные node maps
**Проблема:** Нужно применять разные signals независимо.  
**Решение:** `nodeMap` для "before", `comparisonNodeMapAfter` для "after".  
**Результат:** Независимое управление состоянием каждой сцены.

### Упрощённый рендеринг
**Проблема:** Composer усложняет dual scene рендеринг.  
**Решение:** Composer только для main scene, comparison scene напрямую.  
**Результат:** Уменьшение overhead, упрощение кода.

### Shared camera для синхронизации
**Проблема:** Опциональная синхронизация камер.  
**Решение:** Одна камера когда `comparisonSyncCameras = true`, отдельная когда `false`.  
**Результат:** Простая и эффективная синхронизация.
